# StellarWeaver 实施进度摘要

## CLI 基础（M0–M5，2026-10-25）

| 阶段 | 主要交付 |
| --- | --- |
| M0 | **工程基线。** 建立 Python `src` 包、uv 锁定环境、TOML 配置和共享模型接口。提供可用脚本或回调驱动的 FakeModel，接通 `chat`、`exec`、`version` 和 `doctor --offline`。<br/>**验收。** 在 Windows 和 Python 3.12.6 上核对离线环境、CLI 帮助、版本及本地诊断。 |
| M1 | **工具与执行。** 实现文件枚举、读取、搜索、新建、编辑、命令执行及两项 Git 查询。Agent 逐轮检查参数、路径、授权和预算。编辑前核对 SHA-256，命令记录真实退出码，工具意图和结果写入 SQLite。<br/>**验收。** FakeModel 在临时 Git 仓库完成读取、修改及复测，真实 unittest 退出码从 `1` 变为 `0`。阶段检查 107 项通过、2 项跳过。 |
| M2 | **真实模型与流式续聊。** 接入 DeepSeek Chat Completions。SSE 先聚合工具名、参数和 ID，再执行完整工具调用。CLI 追问沿用原会话，每项新任务重新计算运行预算。<br/>**验收。** DeepSeek 修复临时仓库中的分页校验问题，使用 7 次模型请求和 10 次工具调用，真实测试退出码 `1 → 0`，独立检查通过 14 条断言。 |
| M3 | **恢复与上下文。** 加入 SQLite schema 2、检查点、会话列表、回放、导出及恢复。中断后以哈希核对文件状态，将未确认的命令留待人工核对。按目录读取 `AGENTS.md`，用 Python AST 生成 repo map，并按完整工具回合压缩历史。之后将默认窗口配置提高到 100,000 tokens。<br/>**验收。** 用真实进程退出覆盖文件写入未记账和命令结果未保存两类场景。阶段检查 307 项通过、5 项跳过，后续 100k 窗口另有专项回归。 |
| M4 | **扩展与改动管理。** 从受信目录按需加载 Skills，通过本地 stdio MCP 发现和调用工具。记录 Git 启动基线，`/diff` 区分已有改动、Agent 内置操作及其他变化，`/undo` 按路径、哈希和权限核验后单步撤销。<br/>**验收。** 离线演示验证技能引导工具调用，以及 MCP 连接和关闭。扩展专项 26 项通过，CLI/UI 专项 64 项通过。 |
| M5 | **独立评测与分发。** 建立 20 题固定任务集，使用独立行为断言、改动范围和运行终态评分。保存题目版本、原报告、评分规则和重评分收据，并检查 wheel 与 sdist 的内容和加载。<br/>**验收。** FakeModel 参考动作通过 20/20，验证了工具和评分链路。DeepSeek 每题实际运行一次，独立初评 19/20。修正 Q01 的额外读取判定后，使用原记录重评分为 20/20，新增模型调用为 0。 [内部评测结果](00_Sample_Run.md) |
| V1 补充验收 | 扩展运行总时限覆盖范围，补齐 Windows 受管子进程回收、授权期间指令变化复检、Git 基线对照和分发排除规则。该批次全量离线检查 471 项通过、4 项跳过。随后为普通终端缺 Git 的启动场景另跑了 21 项专项回归。 [CLI 实现规范](01_CLI_AGENT_PLAN.md) · [V1 验收](01_CLI_AGENT_RES.md) · [复现命令](../EVAL.md#复现入口) |

## Web 工作台（G0-G5，2026-11-16 至 2026-11-18）

| 阶段 | 主要交付 |
| --- | --- |
| G0–G1 | **只读工作台。** React 通过 REST 在登记项目中提交任务，FastAPI 与 CLI 复用 Agent 装配。PostgreSQL 保存运行、消息、工具意图及结果，前端用 SSE 查看时间线，刷新后按游标补读。<br/>**验收。** PostgreSQL 17 集成测试覆盖租户边界和重复提交。Edge 用真实 Git 仓库验证文件枚举与刷新恢复，Agent、CLI、恢复与预算相关回归 66 项通过。 |
| G2 | **浏览器修复闭环。** 在工作台查看差异、逐项批准编辑或测试、取消运行及下载 JSON 报告。编辑落盘前再次核对哈希与项目指令。测试证据绑定文件快照，后续编辑会使旧验证过期。<br/>**验收。** Edge 在临时仓库跑通审批、刷新、取消和报告交付，离线修复的真实测试退出码为 `1 → 0`。另一次 DeepSeek 试跑完成读取和经批准的编辑，测试状态为未运行。 |
| G3 | **持久队列与部署。** 把运行记录和 `run_jobs` 在同一事务写入，独立 worker 核对领取归属。Compose 组织 PostgreSQL、迁移、API、worker 与前端。已领取任务异常退出时保留进度和未确认操作。<br/>**验收。** 用不同 API 进程验证重启后任务只被领取一次。强制终止覆盖审批前和运行测试中两种情况，另验证数据库转储恢复及容器重建。队列批次 35 项、Compose 批次 40 项相关回归通过。 |
| G4 | **任务隔离与审阅。** 从项目已提交的基线创建线程专属 worktree，原线程续问可以复用工作区。验证命令在一次性 Linux 容器内运行。可按改动块审阅、导出，并在同基线的新 worktree 应用选中补丁后复验。<br/>**验收。** 使用 PostgreSQL、Docker 和 FakeModel 覆盖同仓库双任务、凭据隔离、超时清理、原线程续接及部分补丁复验。该阶段全量检查 499 项通过、4 项跳过。 |
| G5 | **团队试点与执行服务。** 引入 OIDC、成员角色、项目授权、提交限流、活跃任务和模型用量配额及审计。专用执行服务负责启动验证容器，worker 通过内部网络分派验证。<br/>**验收。** 双账号分别修复并导出补丁，验证容器可并行运行。签名 OIDC 夹具通过登录和注销检查，执行服务重启后清理遗留容器，运行中的验证保留未确认状态。该阶段全量检查 501 项通过、4 项跳过，Edge 端到端 2 项通过。实际组织身份源、生产 HTTPS 和数据库与状态卷的联合恢复仍待验收。 |
