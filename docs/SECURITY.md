# 工具安全、授权与评测

StellarWeaver 根据工具实际使用的路径、数据和执行器判断风险。策略预设定义可用操作，必要时由用户批准具体调用。项目内容、`AGENTS.md`、技能、日志、搜索结果和 MCP 返回值都可能带有不可信指令，授权由程序策略、可信配置和用户决定提供。

## 资产与信任边界

| 边界 | 保护目标与实现 |
| --- | --- |
| 工作区文件 | 内置工具按工作区解析相对路径，检查解析后的最终位置，并过滤受保护路径和运行状态目录。写入前复检目标及可用的版本哈希。 |
| 外发数据与扩展 | `ds_search` 自动发送通过输入检查的公开查询，独立搜索请求只包含本次查询。命中保护规则的查询直接拒绝。CLI 启动 MCP 需可信配置和独立授权，调用工具时还需检查服务身份与参数交接。 |
| 技能目录 | 工作台读取服务端指定的只读共享技能。成员可单独授权源项目的 `.stellarweaver/skills`。手动选用的版本按 SHA-256 复核，技能正文仍作为模型输入，后续操作按当前工具策略授权。 |
| 进程与容器 | 宿主命令随当前系统用户运行。其工作目录限定入口，进程的文件和网络能力由执行环境决定。Web Compose 的验证执行器接收受限快照，只接受固定命令或受控开发操作，任务容器默认断网并设资源边界。 |
| Web 租户与审批 | PostgreSQL 行级隔离与应用查询共同限制租户和项目访问。审批关联租户、运行、操作指纹及有效期，由 worker 原子消费。 |
| 撤销与导出 | 撤销从原线程最新运行发起，在项目私有 worktree 校验操作记录、文件哈希与备份后执行。导出沿用运行可见性，选取可见对话、工具元数据和验证摘要，对凭据模式进行遮盖。 |

## L0-L3 风险分级

等级按单次调用的实际能力计算，覆盖从工作区内读取到硬拒绝。分类函数给出处理建议，最终授权还要应用当前预设、已登记授权和可信 Hook。同一个命令在受控执行器中和在宿主机上可以得到不同等级。 [风险分类](../src/stellarweaver/policy/risk.py) · [授权判定](../src/stellarweaver/policy/__init__.py)

| 等级 | 概念定义 | 典型调用与当前处置 |
| --- | --- | --- |
| **L0 受限读取** | 工具读取已授权范围内的文件、索引或 Git 状态，或发送通过检查的公开网页查询。 | `read_file`、`search_text`、`git_diff`、Python 导航工具和公开的 `ds_search` 查询属于此类。默认直接放行，可信 `PreToolUse` 可要求额外审批。 |
| **L1 工作区变更或受控执行** | 调用会改变工作区内容、准备待审改动，或将输入交给已配置且有自身约束的执行器。路径、文件版本、命令或执行环境可复核。 | `create_file`、`edit_file`、`stage_patch`，以及通过配置的执行器运行测试、Ruff 或语法检查，均处于此级。自动执行范围由下文运行模式决定。 |
| **L2 宿主执行或扩展交接** | 调用使用宿主进程能力，或把参数交给外部扩展组件。MCP 工具声明为只读时，参数交接仍属于这一类。 | 宿主 `run_command`、MCP 启动或调用属于此类。交互批准限单次。部分 CLI 命令和扩展可以匹配精确配置授权。 |
| **L3 硬拒绝** | 准备完成的调用命中不可通过审批覆盖的保护规则。 | 例如搜索查询含明显的本地私有路径或凭据特征，或者 MCP 启动配置试图传入受保护的凭据环境变量。系统记录判定理由并直接拒绝。 |

越过工作区、访问受保护路径及非法路径也会直接被拒绝。这些检查发生在风险评估之前，Journal 记录 `security.guard_denied` 和理由代码，如 `PATH_OUTSIDE_WORKSPACE`。完成准备后才会生成 `security.assessed`，包含操作 ID、等级、能力、执行器和判定理由。需要审批时，工作台卡片显示风险信息。 [路径守卫](../src/stellarweaver/tools/workspace.py) · [工具事件](../src/stellarweaver/tools/registry.py) · [审批卡](../frontend/src/conversation.tsx)

## 运行模式与分流

| 模式 | 放行及审批规则 |
| --- | --- |
| **只读** | 允许受限读取，包括已注册的公开网页搜索。项目编辑与命令由策略拒绝。 |
| **修改** | 沿用原逐项审批。普通创建、编辑、验证和补丁暂存保留各自的审批路径。 |
| **auto** | 可写项目的新任务默认选择。L0 直接执行，普通创建、编辑和可信沙箱登记的固定验证或结构化开发操作自动执行。补丁暂存和需授权的 L2 操作进入单次审批。 |
| **SWE-bench 无人值守** | 允许当前题工作区的读写、精确授权的固定容器检查及实验明确启用的结构化开发工具。宿主执行、网页搜索和 MCP 不在允许范围内。超范围调用返回拒绝，批次保留该题终态并继续。 |

L3 硬拒绝对所有模式生效。自动执行的命令必须来自可信代码实际绑定的受限执行器。通用已注入命令接口或任意 argv 选项本身不构成自动授权；固定命令匹配完整 argv 与 cwd，结构化开发操作匹配实际注册项。CLI 可用 `ask`、`read-only` 或 `workspace-edit`，无交互入口时，仍需审批的调用会被阻止。 [使用与配置](USAGE.md#会话策略和改动)

## 授权与执行顺序

1. 注册表验证工具参数，准备规范化调用，并检查工作区和目标。随后评估风险并记录分类结果。
2. 对通过硬边界的调用，运行时检查适用的项目指令，可信 `PreToolUse` 可继续、要求审批或拒绝。确实进入交互审批时，先调用 `PermissionRequest`。执行前 Hook 超时、异常或返回无效结论会中止操作。
3. 通过授权后复检注册项、策略、Hook、执行器、操作指纹和目标状态。持久化执行意图，再做一次复检后调用执行器。
4. 执行后运行 `PostToolUse`，它可记录观察结果或扣留输出。工具结论随后写入 Journal。Web 批准只消费一次，过期或指纹变化需重新请求。

Hook 由受信程序在 `HookManager` 注册，只能加强限制。CLI 的宿主命令与 stdio MCP 以当前系统用户运行，Docker 隔离以配置的执行路径为准。搜索保护规则检测明显的凭据特征和本机路径，授权事件仍标记 `network:public-search-query`。正常模型请求遵循所选 Provider 的数据边界。 [可信 Hook](../src/stellarweaver/policy/hooks.py) · [Web 审批](../src/stellarweaver/web/approval.py) · [隔离环境](ARCHITECTURE.md#web-执行环境)

撤销由用户确认后入队。worker 只处理最近一次符合条件的内置创建或编辑，先记录意图，再恢复文件并追加结果。哈希不匹配时保留当前文件，未确认的撤销在恢复记录中展示。导出 HTML 对内容进行转义并使用静态展示，运行记录不包含原始模型推理。 [Web 撤销](../src/stellarweaver/web/undo.py) · [导出实现](../src/stellarweaver/web/run_export.py)

## 本地工具边界评测

```powershell
uv run --locked --offline python -m stellarweaver.evals.local_fixtures
```

固定夹具使用临时工作区、FakeModel、真实工具注册表、SQLite Journal 与内存接收器。可通过 `--output .validation/新文件.json` 保存制品，已有输出受到覆盖保护。报告保留夹具与判定代码哈希、任务 ID、工具终态、文件前后哈希和模拟接收记录。

| 预注册组 | 场景 | 独立判定 |
| --- | --- | --- |
| 边界 | 分别读取和修改临时 `.env` 哨兵 | 比对文件前后哈希，检查返回内容是否包含合成哨兵。 |
| 边界 | 查询含合成凭据特征 | 返回 `NONPUBLIC_SEARCH_QUERY`，内存接收器收到 0 次查询。 |
| 正常任务 | 普通公开查询 | 接收器收到一次查询，内容与原查询一致，审批回调调用 0 次。 |
| 正常任务 | 定位文件并解决一次版本冲突 | 核对搜索结果、冲突状态与最终文件字节。 |

报告分别统计边界场景、正常任务、未授权副作用、工具与模型调用量及审批次数。历史 M2 报告保留当时逐次审批的场景定义和证据。夹具测试验证本地应用层的具体操作，真实出站网络、操作系统沙箱、模型对注入的判断和总体攻击成功率需要独立验证。 [夹具源码](../src/stellarweaver/evals/local_fixtures.py) · [M2–M4 验收](HARNESS_ACCEPTANCE.md#m2-m4-固定夹具与授权)

## 外部套件可行性

- CodeIPI 的 Inspect Evals 配置定义了隔离环境、任务判定、分类规则与评审器。StellarWeaver 可将日志和制品映射到相应格式。要取得原生可比结果，需要固定源代码和数据版本，保留官方评分器与环境语义，并核对许可和外部调用。 [CodeIPI 官方说明](https://ukgovernmentbeis.github.io/inspect_evals/evals/ipi_coding_agent/)
- RepoGuardBench 包含仓库场景和正常任务对照。可复用 StellarWeaver 的题号、操作事件、文件哈希和结果记录接口。适配前需核对样本版本、许可、隔离和官方判定，改动过的子集按适配结果报告。 [RepoGuardBench 官方仓库](https://github.com/DaoyuanLi2816/RepoGuardBench)

外部套件目前处于方案核对阶段。评测代码、数据和镜像仍待准入登记，正式结果尚未生成。 [评测协议](EVAL_PROTOCOL.md)
