# StellarWeaver × SWE-bench Lite 实施与实验方案

本方案以 DeepSeek `deepseek-flash` 为主要模型，使用 SWE-bench Lite 研究真实仓库修复效果、运行成本和验证可靠性。实验按「小样本检查 → 23 道 `dev` 开发与验收 → 冻结配置后的 300 道 `test`」推进。当前可执行命令、具体镜像要求和已运行结果统一见[验证文档](EVAL.md#swe-bench-lite-批量评测)。

## 架构与数据边界

| 环节 | 输入与职责 | 可对外提供的证据 |
| --- | --- | --- |
| Agent | 获取公开题面、仓库名和固定基线，使用每题独立工作区。可见测试按配方在受限的断网容器内执行。评测关闭网页搜索，工作区限制 Git 历史，执行环境不继承 API Key、数据库凭据或宿主配置。 | Agent 终态、事件、用量、候选 Git diff、是否可应用及快照标识。 |
| 评分 | 与 Agent 分开读取官方测试字段、评分镜像和候选补丁，在独立环境应用补丁并判定 `FAIL_TO_PASS` 与 `PASS_TO_PASS`。参考实现、隐藏测试和评分专用字段只供评分或离线分析。 | 补丁哈希、镜像摘要、评分器版本、评分 ID、退出与错误状态及原始报告。 |
| 汇总与展示 | 汇总固定实验清单内的所有任务，保留 Agent、补丁和评分各自的状态。展示所需脱敏证据，沿用现有 Journal／Worker 和工作台。 | 按实验和题目组织的指标、日志索引、版本来源及失败类别。 |

每次实验冻结数据集修订、题号清单、基线提交和评分器版本。候选导入、重评分和重汇总读取此前保存的制品。不同候选使用独立评分 ID，只有经过校验的同一配置和候选才允许复用结果。对缺失依赖、超时、空补丁、补丁不可应用及评分基础设施异常分别归类。

## 阶段交付与验收

| 阶段 | 进展与下一项验收 |
| --- | --- |
| Phase 0 · 基线核对 | 当前调用链和历史结果已整理。每轮正式对照前冻结代码、模型、工具、预算和运行环境指纹。 |
| Phase 1 · DeepSeek Thinking | 主链路支持 Thinking High，流式和非流式工具回合保存协议完整性。现有验收覆盖回传、压缩、跨进程续接和 Non-thinking 路径。 [模型适配记录](EVAL.md#deepseek-thinking-接入) |
| Phase 2 · 数据集适配 | 批量入口已实现准备、运行、导入、导出、独立评分和汇总。已有三题小样本及 23 题清单。下一步补齐环境配方，验收全部 `dev` 题的终态、续跑、离线评估和失败归类。冻结配置后再运行正式 `test` 基线。 [试跑证据](EVAL.md#phase-2-多仓库试跑记录) |
| Phase 3 · 实验管理 | 已有 Manifest、Attempt、Score、Evidence 契约、独立收据和离线重汇总。下一步用完整开发集验收跨批次查询、断点续跑和重评分。 |
| Phase 4 · Harness 优化 | 每项能力独立开关，配套回归测试和可观测事件。在固定预算与题目下测试单项改动，再评估组合和移除单模块后的变化。 |
| Phase 5 · 工作台视图 | 已支持切换发布报告、按题号和评分状态筛选、查看逐题候选与评分，以及按题号配对比较。后续用完整开发集验收并扩展跨仓库与失败类型的检索。 |

### Phase 3 数据契约

| 记录 | 字段与标识 |
| --- | --- |
| 实验 | `experiment_id`、代码及数据集修订、评分器版本、模型及 Thinking 设置、配置和提示哈希、工具 schema 哈希、预算。 |
| 题目尝试 | `experiment_id`、`instance_id`、`attempt_id`、关联运行和工作区标识、起止时间、运行终态、终止原因及候选 SHA。 |
| 用量 | 请求和工具次数、输入／缓存命中／输出 token、是否估算、运行时价格版本及费用。 |
| 评分 | 独立评分 ID、候选哈希、是否成功应用、官方评分状态、评分器版本及报告位置。 |
| 制品 | 脱敏事件、补丁、日志、环境指纹及字节哈希。 |

运行和评分状态分别保存。例如 Agent 可以达到 `completed`，评分仍可能是 `unresolved`、`not_evaluated` 或 `evaluation_error`。同一实例跨实验关联依赖数据集修订和 `instance_id`，同一实验内依赖 `attempt_id` 区分重试。

### Phase 4 实验模块

| 模块 | 实施与比较指标 |
| --- | --- |
| H1 · Issue 感知的定位 | 在 Python AST repo map 上结合题面关键词、符号、异常栈、相关测试和调用关系，对文件排序后按需读取。以 Top-1／Top-5、首次有效编辑前用量、定位时间和官方通过率比较。参考补丁的文件只用于离线判定。 |
| H2 · 失败反馈与恢复 | 区分断言、依赖或导入、语法或运行时错误、补丁冲突、超时、权限及重复无进展。根据真实证据选择检查、重编辑、按哈希回退或停止。记录重复失败和恢复结果。 |
| H3 · 任务上下文与前缀缓存 | 比较当前压缩与保留题面、已核实假设、关键路径、补丁和测试证据的版本。稳定提示前缀及工具 schema，同时验证 Thinking 消息和工具 ID 序列。观察缓存命中、累计输入和每个通过任务的费用。 |
| H4 · 自适应预算 | 在相同总预算下，按任务进展调整定位、编辑和验证的资源分配。比较通过率、预算耗尽率、时延和成本。 |
| H5 · 多候选或多 Agent | 待 H1–H4 有可靠证据后评估，单独记录候选数、选择规则和额外资源。 |

## 对照设计

| 组别 | 配置 | 用途 |
| --- | --- | --- |
| A0 | StellarWeaver + DeepSeek Flash Non-thinking | 历史行为参考，可重新建立受控基线。 |
| A1 | A0 的同一环境和预算，启用 Thinking High | 测量模型设置影响。 |
| B0 | Thinking High + 冻结的当前 Harness 和总预算 | 正式 Harness 基线。 |
| B1–B4 | 从 B0 依次增加 H1–H4 | 记录组合的增量效果，并在固定基线上做单变量对照。 |

固定代码版本、数据集修订、题目与顺序、基线提交、模型 ID 与可确认的版本、Thinking 强度、端点、可用采样参数、系统提示、工具 schema、权限、上下文窗口、预算和运行环境。独立评测入口的现行窗口为 100k。无法确认 API 别名对应的实际模型版本时，记录 `model_revision_unverified`。优化模块直接改变的设置单列，任务之间隔离上下文。 [评测协议](EVAL_PROTOCOL.md)

用 `dev` 调整设置并验证故障恢复。正式 `test` 基线需先冻结配置，记录预算和资源需求，经确认后启动。记录对 `test` 结果的接触与后续调参情况。重复采样的资源和结果单列，关键设置可在 `dev` 先做每题三次。对同一实例的通过差异使用 McNemar 或配对 bootstrap 并报告区间。对历史公开 Issue 考虑训练污染，并可另用独立任务检验泛化。

## 指标、制品与交付

- **通过率**使用官方 `resolved` 数除以计划任务数，另报已评分数、未开始数和基础设施错误数。
- **补丁、工具与恢复**分别报告空补丁率、有效候选的应用率、工具错误率和预定义可恢复故障的恢复率，授权拒绝和取消单独计数。
- **用量、费用与耗时**区分 API 报告与估算，缓存命中计入输入总量。费用使用运行时价格快照，`Cost per Resolved` 在通过数为零时记为 `N/A`。时延报告 P50／P95，并区分 Agent 与独立评分。
- **制品**保存 `manifest.json`、`predictions.jsonl`、`task_results.jsonl`、官方评分、日志、`aggregate.json` 及按题号配对的对照表。发布时提供脱敏配置和公开汇总。
- **最终验收**覆盖题目和评分资料隔离、完整出分及恢复规程、配置指纹与原始证据可追溯、H1–H4 可独立消融，以及工作台可从实验汇总查到每题候选和评分。未运行的实验组保留 `not_run`。
